# ADR-001: v2 立项与重写哲学

- 日期：2026-09-02
- 状态：已接受

## 背景

前作 aegis-agent-platform（自研多租户客服 Agent 平台，v1.0，测试 1003）从零实现了三层架构的全部机制：LLM 网关（档位路由/熔断/限流/缓存/计量）、Agent 运行时（循环闸门/事件溯源/HITL/崩溃恢复）与多租户客服业务层。全自研换来了对每个机制的完全掌控，也意味着大量与业务无关的基础设施代码需要自行维护。

LangChain 1.x / LangGraph 1.x 世代已把循环骨架（create_agent）、middleware 挂点、检查点持久化等能力官方化。一个前置 spike 仓（278 测试）逐模块验证了自研实现与框架能力的映射关系，产出了逐文件的【替代/保留/丢失】账本；姊妹项目 Argus（LangChain/LangGraph + 现成库，151 测试）验证了"能用库就不自研"的产品仓形态。

## 决策

1. **框架原生重设计**：以 LangChain/LangGraph + 现成生态库重写 Aegis 平台。语义等价锚定在**行为契约**上（六类网关异常契约、六道终止闸门+终止原因八值、审批五态 CAS、四大多租户对抗场景等），不逐文件复刻自研实现；能用现成库就不自研，框架替不掉的策略与语义显式自建。
2. **spike-then-rewrite 双仓形态**：spike 仓自由实验并沉淀结论，本仓（产品仓）按验证过的结论全量重写；两仓同步单位是**结论**不是代码——不 import、不 path dep。
3. **范围=语义等价，不扩展**：v1 的硬性非目标（多渠道接入/精美前端/模型微调/K8s 实操/Agent 市场/异地容灾）全部继承；v1 未做的扩展项不自动进入本仓范围，要做单独立 ADR。

## 后果

- **差距记账义务**：v1 每项语义在 v2 的命运（保留/降级近似/放弃）逐项显式记录（README 记账表），不允许沉默丢失——事件溯源让渡为检查点快照、确定性回放的替代方案、分布式熔断语义的降级等，都是必须显式裁决的设计题，不是实现细节。
- **框架默认能力不许静默启用**：框架自带而 v1 未纳入范围的能力（如流式 tool-call 增量解析、自动摘要触发），每项要么显式接受并登记，要么显式关闭。
- 两版实现构成同一组语义在"全自研"与"框架原生"两种形态下的对照样本：取舍差异本身是本项目的核心产出之一。
