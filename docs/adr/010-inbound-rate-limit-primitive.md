# ADR-010: 入站限流原语

- 日期：2026-09-05
- 状态：已接受

## 背景

前作的入站限流是 API 层依赖：租户维度键、Redis Lua 令牌桶、即问即答（超限立刻 429，`Retry-After` 取桶的真实等待提示）、Redis 不可用时降级为进程内桶且粘滞；与出站限流明确分工——入站保护自己（请求进门前拒绝），出站保护供应商（候选环内可短排队）。本仓总计划把入站原语钉在 fastapi-limiter 0.1.6（Redis Lua 固定窗计数，多副本共享）；ADR-008 把入站部分移出，待本仓对框架依赖注入形态的探针复核后单独裁决。端点挂载与阈值归后续里程碑，本 ADR 只裁决原语。

本仓 venv 探针事实（fastapi 0.141.1 / starlette 1.6.0 / fastapi-limiter 0.1.6 / redis 5.3.1）：
- 库自带的 `RateLimiter` 依赖在每次请求里扫 `request.app.routes` 取 `route.path` 拼键：经 `include_router` 挂载的端点会碰到 `_IncludedRouter`（无 `path` 属性）而抛 `AttributeError`；直接挂在 app 上时键里含路由序号与依赖序号，前面增删一条路由即漂移；默认 identifier 无条件取 `X-Forwarded-For` 首段；未 `init` 时抛通用异常（fail-closed，响应 500）。库的 `init` 把客户端、前缀、脚本 sha 存为类属性，是进程级全局态。
- 库的 Lua 计数：窗内首个请求 `SET ... PX`，之后 `INCR` 不续期（固定窗）；超限返回键的 `PTTL` 毫秒（整数）；`times=0` 时首个请求仍走 `SET` 分支放行。
- `evalsha` 在 `SCRIPT FLUSH` 后与传入从未加载的 sha 时抛同一个 `NoScriptError`；sha 为 `None` 时是 `DataError`。
- FastAPI 依赖按 `dependencies=[...]` 列表顺序解析，`HTTPException` 抛出后后续依赖与 handler 都不执行；429 体为 `{"detail": ...}`，`headers` 原样透传。
- 快速失败参数的 Redis 客户端对无人监听的端口抛 `RedisError` 家族异常（`TimeoutError`），上传脚本的路径同样。

## 决策

1. **只借库的 Lua 脚本，不借它的装配形态；依赖移除**（`core/limits.py`）。固定窗计数脚本抄入本仓并注明出处，只改一处：已满分支给 `PTTL` 加下限 1（键在过期那一毫秒 `PTTL` 为 0，原版会被调用方当成放行）；`RateLimiter` 依赖（崩溃、键漂移）、默认 identifier（可伪造身份）、默认回调（英文体、fail-closed）、类属性式 `init`（全局态）一概不用。理由与 ADR-007 翻案同源：库的核心算法值得借，库的装配形态与本仓"真实依赖只在组合根聚合、其余靠注入"相悖时不借。
2. **限流器是注入的进程级共享件**：`InboundLimiter(redis, probe_interval)` 由进程入口的 lifespan 创建、`start()` 预载脚本、挂在应用状态 `app.state.inbound_limiter`；与熔断、缓存共用同一个快速失败 Redis 客户端；关停时把挂点置空，客户端由 lifespan 自己关闭。无 Redis 配置时挂点为空。依赖工厂 `rate_limit(scope, times, seconds, *, identify, detail)` 返回的依赖在请求时从 `request.app.state` 取限流器，取不到即放行——测试各挂各的实例，互不干扰；同一进程的多个应用不共享状态。
3. **键 = `{prefix}:{identity}:{scope}`**，身份段只有 `tenant:` / `user:` / `ip:` 三族且拼装点唯一；scope 字符集、`times` 与 `seconds` 为不小于 1 的整数在挂载时校验（启动即炸；`times=0` 会被 Lua 放过首个请求，浮点秒会让 `PX` 参数被 Redis 拒收而把每个请求当成存储故障）。键稳定、可读、可按租户 `SCAN`，不随路由增删漂移。
4. **固定窗替代前作令牌桶，记入差距记账表**：固定窗在窗边可容许两倍阈值的突发、无平滑补给，不管瞬时密度；`Retry-After` = 当前窗剩余时间向上取整且不小于一秒（仍是真实提示而非常数）。接受的理由：入站闸只防刷不做流量整形，"每窗 N 次"比"速率 + 桶容量"更易向人解释，且计数脚本现成；瞬时密度若需约束可在同一端点叠一个短窗；前作 Lua 令牌桶若成为需求可整段平移。
5. **即问即答，不排队**：超限立刻 429。默认话术住 `core/limits.py`（话术单一事实源的登记例外：core 不得反向 import engine），挂载处可注入替换。
6. **身份**：默认直连对端地址，不信任 `X-Forwarded-For`（反代场景由部署面按可信代理改写 `client`）；租户/用户身份函数由挂载处注入（后续里程碑接 JWT），且认证依赖必须排在限流依赖之前——按身份计费的动作必须先认证，否则未认证请求能以他人名义消耗额度。429 先于 handler：超限探测不出任何业务事实。
7. **fail-open 两层 + 降级粘滞**（前作三条规则平移，与 ADR-007 决策 6 同款）：未挂载（无 Redis 配置、测试、已关停）直接放行——限流是护栏不是核心功能的前置依赖；运行期任一 Redis 触点异常即降级为进程内固定窗（Lua 算法的直译，有界 LRU，被拒的键也算最近使用），`probe_interval` 内不再碰 Redis，顺路探针失败顺延；**只有被指派的那次探针成功才恢复**并作废本地窗——健康期发出、降级后才返回的迟到成功只返回自己的裁决，不改状态（否则故障瞬间在途的每个响应都会把限流器翻回去再降级一次，每翻一次清一次本地窗）；`start()` 时 Redis 不可达不炸进程：直接进入降级态，脚本由首个成功探针加载。`NoScriptError` 是重载路径不是故障：重载脚本再试一次。
8. **多副本口径**：共享态精确（Redis 单点计数）；降级期各副本各数各的，上限为阈值乘以副本数——不按副本数折算，宁可故障期短暂多放，不误拒合法流量；单副本时两者相同。
9. **端点挂载与阈值归后续里程碑**；本步只交付原语，阈值不进全局配置，进配置的只有降级期探针间隔。

## 实证（探针）

复现方式：临时 FastAPI 应用经 `httpx.ASGITransport` 驱动；库 `RateLimiter` 依赖分别经 `include_router` 与直接挂载；自建依赖原型直接调用 `evalsha`；`SCRIPT FLUSH` 后再调；快速失败客户端指向无人监听端口；`dependencies` 列表放三个记录执行顺序的依赖。定性结论：
- 经 `include_router` 挂载的端点上库依赖抛 `AttributeError`；直接挂载时键含路由序号，前面多插一条路由后同一端点的键改变；伪造 `X-Forwarded-For` 的请求各得一把键。
- 自建依赖：前 N 次放行、第 N+1 次 429，体为 `{"detail": <话术>}` 且带 `Retry-After`；键为 `{prefix}:{identity}:{scope}`，值为计数，`PTTL` 不超过窗口；第二次计数后 `PTTL` 已在递减（固定窗）。
- `SCRIPT FLUSH` 后依赖内重载脚本、请求继续放行；坏 sha 与被清空是同一异常。
- 无人监听端口上 `evalsha` 与上传脚本均在一次短超时内抛 `RedisError` 家族异常。
- 以上事实由 `tests/core/test_limits.py`、`tests/test_main.py` 钉住（真 Redis 走契约与脚本重载；可编程替身与假时钟走降级、粘滞、探针与恢复；两个应用各挂各的限流器互不连累）。

## 后果

- 前作即问即答、真实 `Retry-After`、租户维度键、Redis 挂降级粘滞四项语义全部保留；桶算法退为固定窗，窗边突发与无平滑补给记入差距记账表。
- 限流器与熔断、缓存同一装配形态：lifespan 创建、注入、关停摘下；没有进程级全局态，测试不需要清理钩子。
- 依赖基线减一：fastapi-limiter 由运行时依赖移除，本仓只保留其固定窗 Lua（十余行，注明出处）；库的升级或消亡不再影响本仓。
- 降级期的本地窗是近似：多副本各数各的、LRU 淘汰再回来的键从新窗开始；精确性随 Redis 恢复而恢复。
- 熔断与缓存两个同款粘滞实现的恢复判定仍是“降级期任一成功即恢复”，同样会被在途的迟到成功翻回；修正为“只认指派探针”留待后续里程碑一并处理。
- 阈值与身份函数由挂载处决定：本原语不含任何端点知识，后续里程碑为各端点挂载时须同时决定认证依赖的顺序。
