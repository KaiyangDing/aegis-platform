# 崩溃恢复演示记录（2026-09-09，M2.9 落库后复跑，真 Postgres）

- 命令：`uv run pytest tests/engine/runtime/test_runtime_recovery.py -k kill9 -s -q`
- 环境：本机 Windows 11，`docker compose up -d postgres redis`（pgvector/pgvector:pg16），测试库 `aegis_test` 由 conftest 重建 schema 并 alembic 到 0002；
  LangGraph `AsyncPostgresSaver` over psycopg 连接池、`durability="sync"`；事件循环 Selector；`AEGIS_FAKE_LLM=1`，模型是剧本候选（零真实调用）；
  langchain 1.4.0 / langgraph 1.2.11 / langgraph-checkpoint-postgres 3.1.2 / psycopg 3.3.5；被测代码 = 已提交的 M2.9（3807a91）及之后的主树
- 口径：崩溃 = 在指定位置抛出 BaseException（框架与运行时的错误处理都接不住，等价于进程死亡；Windows 无 SIGKILL，本仓不做真进程脚本，
  见收尾计划命运表 A5）；恢复 = `AgentRuntime.resume(approval_id=None)` 单入口从最后一个 checkpoint 之后重放；
  断言对象是 events 表（真 PG 落库行）与 sessions 行，不是进程内对象；**不报自愈时长**（时长口径只属前作）。
- 结果：2 passed（11 deselected），与 2026-09-08 稿件验证记录一致

## 演示一：工具副作用之后死亡

工具 `ship` 在拿到幂等键、记录副作用之后抛出 → checkpoint 停在 tools 之前、run_state 留 running → 恢复 → tools 节点重放：
`tool_call` 事件派生同 id 去重命中（日志"重放命中既有 tool_call 事件：以原幂等键重执行，不产生第二把钥匙"）、
工具再执行一次、`tool_result` 以原事件 id 闭合 → 模型收尾 → T4 idle。

```
2026-09-09 21:45:49 [info     ] 重放命中既有 tool_call 事件：以原幂等键重执行，不产生第二把钥匙 tool=ship tool_call_id=d4c76361-32eb-589e-81e7-430835cd7f56
[kill -9 demo/tool] session=s-db5c4a9c events=['user_message', 'llm_call', 'llm_result', 'tool_call', 'tool_result', 'llm_call', 'llm_result', 'assistant_message', 'loop_terminated'] keys=['d4c76361-32eb-589e-81e7-430835cd7f56'] executions=2
```

断言：events 表恰 9 行、seq 1..9 连续、id 全不同、每行带框架任务 id；`tool_result.tool_call_id` == `tool_call.id`；工具执行两次、
下游只见一把幂等键；会话回到 idle。

## 演示二：模型返回之后、llm_result 落盘之前死亡

`llm_call` 已落、`llm_result` 未落 → checkpoint 停在 model 之前 → 恢复 → model 节点重放：`llm_call` 派生同 id 去重命中 →
判定为半截 LLM（日志"重放命中既有 llm_call：半截 LLM 调用作废重发"）→ 补配对 `llm_result(interrupted, cause=replay)` →
下一序号重发（iteration 2）→ 收尾。

```
2026-09-09 21:45:49 [info     ] 重放命中既有 llm_call：半截 LLM 调用作废重发  iteration=1
[kill -9 demo/model] session=s-2cb6df3d events=['user_message', 'llm_call', 'llm_result', 'llm_call', 'llm_result', 'assistant_message', 'loop_terminated'] calls=2
```

断言：events 表 7 行、seq 1..7 连续、id 全不同；第 1 次调用的结果是 `interrupted / replay`、第 2 次 iteration=2 且文本是重发的回答；
模型调用两次；会话回到 idle。

## 登记

- 候选（模型）里直接抛 BaseException 不能模拟"模型调用期崩溃"：langchain-core 1.6.1 `agenerate` 把非 Exception 的 BaseException 当成功结果
  取 `.generations`，以 AttributeError 穿出；演示二改在 llm_result 落盘之前注入，恢复语义相同。
- 无会话锁世界的并发恢复基线（探针 (22)）：两个恢复者同时重放 tools 节点会各执行一次副作用、一方 checkpoint 写入冲突——
  本仓无租约（ADR-012 决策 15），"运行中的会话是否已死"由恢复调用方断言；write-ahead 幂等键让重复执行在下游可去重。
